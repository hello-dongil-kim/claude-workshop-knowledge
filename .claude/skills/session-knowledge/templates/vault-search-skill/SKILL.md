# knowledge-find — Vault 에이전트 검색

설치·색인 없이 Vault에서 의미 검색을 수행한다. session-knowledge(두 번째 뇌 II) 기본 트랙 산출물.
**이 파일을 본인 Vault에 맞게 다듬어 쓴다** (대상 폴더·제외 폴더·frontmatter 필드).

## 설정 (이 부분을 내 Vault에 맞게)

- 검색 대상: `<VAULT 경로 또는 하위 폴더>` (예: 클리핑·정리노트 폴더)
- 제외: `_private/`, 첨부 폴더, `.obsidian/`
- 활용 메타: frontmatter `type` / `tags` / `date`
- 주제 지도: `_moc/_index.md`(있으면 경유)

## 검색 절차 (4단계)

요청을 받으면 아래 순서로 수행한다.

1. **질의 확장** — 질문의 핵심어를 동의어·상위어·한영 병기로 넓힌다.
   예: "집값" → 집값·부동산·전세·매매·주거 / "리텐션" → 리텐션·잔존율·재방문
2. **후보 수집 (grep/glob + 필터)** — 확장어로 대상 폴더를 검색하고, 필요하면 frontmatter(`type`/`tags`/기간)로 좁힌다. 후보가 많으면 `_moc/`에서 가까운 주제를 먼저 골라 범위를 줄인다.
3. **읽기** — 상위 후보의 본문·frontmatter를 실제로 읽는다(제목만 보고 판단하지 않음).
4. **추론 랭킹 + 근거** — 질문 의도에 맞는 순으로 정렬해 상위 5개(기본)를 제시한다. 각 결과에 **왜 관련 있는지 노트의 실제 문장을 1줄 인용**. 확실치 않으면 "관련 약함"으로 표시(추측 금지).

## 출력 형식

```
1. [노트 제목]  (type·date)
   [[파일명]]
   근거: "…실제 인용…"
```

## 옵션 (요청에 포함되면 반영)

- 개수: "top N"
- 필터: "type=clipping만", "tags에 브랜드", "2025년 이후"
- 넓게/좁게: "동의어 넓게" / "핵심 의미만 좁게"

## 한국어 팁

- 조사·어미로 grep이 빗나가므로 어간·명사 위주로 검색어를 잡는다.
- 영문 개념은 한/영 병기로 확장한다.

## 한계 안내 (정직하게)

- 후보가 수백을 크게 넘으면 다 읽지 못한다 → 필터·MOC로 좁히거나, 대규모면 벡터 RAG(session-knowledge B8) 권유.
- 색인이 없어 매번 검색을 새로 한다(항상 최신, 대신 질의마다 수 초~십수 초).

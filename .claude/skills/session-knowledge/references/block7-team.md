# Block 7: (선택) 팀으로 확장 — 개념 청사진

## EXPLAIN

> **전제:** B0~B5 완료. 이 블록은 **실습이 아니라 청사진**이다. 혼자 쓰던 두 번째 뇌를 팀으로 넓힐 때 무엇이 달라지는지 지도만 그린다. (풀 구축은 별도 주제.)

### 개인 → 팀, 무엇이 달라지나

| 차원 | 개인 (지금까지) | 팀 |
|------|----------------|-----|
| 저장 | 내 Vault 한 개 | Git 레포 하나로 통합 |
| 신뢰 | 내가 다 안다 | "누가 쓴, 검증된 지식인가"가 중요 |
| 검색 | 나만 쓰면 됨 | 모두가 같은 지식을 찾음 |
| 변경 | 내가 바로 고침 | 리뷰·승인·되돌리기 필요 |

### 4개 공간 (레이어)

- **`context/`** — 팀 전체 합의·공유 지식 (정식 절차로 **승격된** 것만)
- **`members/{이름}/`** — 개인 작업 공간 (초안·실험)
- **`agents/`** — 공유 스킬·규칙 (회사 + 개인 레벨)
- **`_private/`** — 민감·잡담. **공유·동기화 절대 안 함**

### 승격(promotion) — 개인 지식이 팀 지식이 되는 길

```text
members/{나}/ 초안  +  원본 출처 보관
   → "팀에 공유하고 싶어" 한 마디
   → 에이전트가 PR 자동 작성
   → 자동 검증: 규칙 준수? 기존 지식과 충돌? 위치 추천
   → 사람이 최종 머지 승인
   → context/ 로 팀 지식 확정
```

비개발자에겐 "PR이 뭐냐" 부담 없이 **어디에 적을지만** 안내하고, 리뷰는 에이전트가 처리한다.

### 거버넌스 — 사람 먼저, 나머지 위임

| 사람이 직접 | 에이전트 위임 |
|-------------|---------------|
| `_private` 관리 | 그 외 문서 입수·정리·연결 |
| **삭제·머지 최종 승인** | PR 작성·자동 검증 |
| 민감 권한·보안 | 일상 잡일 |

> 핵심: **사람이 할 일을 먼저 정의**하고, 귀찮은 나머지를 에이전트에 맡긴다. 검증 리뷰는 자동 OK가 아니라 **사람 최종 승인 필수** — 안 하면 즉시 쓰레기장.

### 검색은 어떻게 되나

이번에 만든 검색 엔진은 팀에서도 그대로 쓴다 — 대상이 `context/`(공유 지식)로 바뀔 뿐. "규칙화된 문서 저장소는 오히려 RAG하기 쉽다"는 원리는 팀에서 더 강해진다.

## EXECUTE

실습 없이, 내 상황에 대입해 생각해보세요:

**Step 1: 승격 후보**
- 내 Vault에서 "팀이 보면 좋을, 검증된 지식" 1개는? → `context/` 후보

**Step 2: 비공개 후보**
- "절대 공유 안 할" 자료 1개는? → `_private` 후보

**Step 3: 경계 긋기**
- 팀으로 간다면 "사람인 내가 끝까지 직접 결정할 일"은? (삭제? 민감자료? 머지 승인?)

> ✅ **이렇게 되면 성공:** 내 지식 중 **`context/`로 승격할 것 1개**와 **`_private`로 둘 것 1개**를 구체적으로 대고, "팀에서도 내가 직접 결정할 일" 1개를 말할 수 있으면 성공.

## QUIZ

**문제:** 팀 지식 저장소에서 "승격(promotion)"이란?

| 선택지 | 내용 |
|--------|------|
| A | 개인 공간의 초안이 검증·승인을 거쳐 팀 공유 지식(`context/`)이 되는 과정 |
| B | 오래된 노트를 자동으로 삭제하는 과정 |
| C | 검색 점수가 높은 노트를 맨 위로 올리는 것 |

**정답:** A — 승격은 `members/`의 초안이 리뷰·승인을 거쳐 `context/`(팀 합의 지식)로 올라가는 절차다. B는 삭제(반대 방향)라 틀렸고, C는 검색 랭킹 얘기라 무관하다.

---

**적용 문제 (시나리오):** 팀 Vault를 도입하는데, 거버넌스를 어떻게 잡는 게 가장 건강한가?

| 선택지 | 내용 |
|--------|------|
| A | 효율을 위해 에이전트가 머지·삭제까지 전부 자동 결정하게 한다 |
| B | 사람이 직접 할 일(민감자료·삭제·머지 최종 승인)을 먼저 정하고, 나머지 잡일을 에이전트에 위임한다 |
| C | 모든 결정을 사람이 수동으로 해 에이전트는 안 쓴다 |

**정답:** B — "사람이 할 일을 먼저 정의 → 나머지 위임"이 핵심. 승인 게이트를 사람이 쥐어야 품질이 보존된다. A는 사람 게이트가 없어 쓰레기장이 되고, C는 자동화 이점을 통째로 버려 비효율적이다.

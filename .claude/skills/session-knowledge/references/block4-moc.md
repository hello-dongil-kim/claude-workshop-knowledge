# Block 4: 지식 지도 — Claude가 주제별 MOC 생성

> 🎛️ **지휘자 원칙:** 클러스터링 알고리즘을 배울 필요 없습니다. "주제 지도를 만들어줘"라고 **Claude에게 시키고**, 묶음이 내 주제와 맞는지만 판정하세요.

## EXPLAIN

검색(B2~B3)은 "찾을 때" 쓴다. 그런데 "내 Vault에 **무슨 주제가** 쌓였지?"는 검색으로 안 보인다. 평면 더미를 **항해 가능한 지도**로 바꾼다.

### 평면 더미 문제

노트 수백~수천이 얕게 쌓이면 검색은 되지만 **전체 조망**이 없다. "내가 요즘 뭘 모으나"를 못 본다.

### 해법 — Claude가 읽고 묶는다 (임베딩·KMeans 없이)

기본 트랙은 알고리즘 클러스터링 대신 **Claude의 읽기·추론**으로 묶는다:

```text
① Claude가 노트 제목·frontmatter(·일부 본문)를 훑음
② 의미가 가까운 것끼리 주제로 묶고 이름 붙임
③ 주제별 MOC 노트 생성 (멤버를 [[위키링크]]로)
④ _moc/_index.md 가 진입점
```

대규모(수천+)라 Claude가 다 못 읽으면, B8 벡터 트랙의 자동 클러스터링(KMeans)을 쓴다 — 그건 심화.

### MOC를 어디에 두나

`_moc/`는 **Vault 안**(같은 vault라야 `[[위키링크]]` 연결). 검색 대상과 섞이지 않게 폴더만 분리.

### 갱신 주기

매번 다시 만들 필요 없다. 노트가 **충분히 더 쌓였을 때** 재생성(월 1회쯤). 너무 잘게 쪼개지면 "더 큰 덩어리로 묶어줘", 뭉치면 "더 잘게"로 Claude에게 조정 지시.

## EXECUTE

**Step 1: 주제 지도 만들기 시키기**
- "내 Vault 노트들을 제목·태그·일부 본문을 보고 비슷한 주제끼리 묶어서, 주제별 MOC 노트(`_moc/주제.md`, 멤버를 `[[위키링크]]`로)와 진입점 `_moc/_index.md`를 만들어줘. 묶음이 너무 많거나 적으면 알려줘."

**Step 2: 지도 열어보기**
- Obsidian에서 `_moc/_index.md`를 열어 주제 목록 확인. 한 주제를 열어 멤버 링크 + 그래프뷰 연결 확인.

**Step 3: 조정**
- 겹치거나 과하면 "이 두 주제 합쳐줘 / 이 주제 더 잘게 나눠줘"로 다듬기.

> ✅ **이렇게 되면 성공:** `_moc/_index.md`에 주제 N개가 생기고, 한 주제를 열면 관련 노트가 `[[위키링크]]`로 묶여 있으면 성공 — 평면 더미가 지도가 됐다.

## QUIZ

**문제:** 기본 트랙에서 주제 지도(MOC)를 만드는 방식은?

| 선택지 | 내용 |
|--------|------|
| A | Claude가 노트를 읽고 의미가 가까운 것끼리 묶어 주제 노트를 만든다 |
| B | KMeans 같은 임베딩 클러스터링 알고리즘을 반드시 돌린다 |
| C | 폴더를 주제별로 새로 나눈다 |

**정답:** A — 기본 트랙은 임베딩 없이 Claude의 읽기·추론으로 묶는다. B는 심화(B8) 벡터 트랙의 방식이고, C는 폴더 재편이라 MOC(링크 기반 지도)와 다르다.

---

**적용 문제 (시나리오):** MOC를 만들었더니 비슷한 주제가 "브랜딩 / 브랜드 전략 / 브랜드 사례"로 잘게 쪼개졌다. 가장 적절한 조정은?

| 선택지 | 내용 |
|--------|------|
| A | Claude에게 "이 셋을 하나의 큰 주제로 합쳐줘"라고 시킨다 |
| B | 노트를 더 모은 뒤 vault를 처음부터 다시 만든다 |
| C | MOC를 포기하고 검색만 쓴다 |

**정답:** A — 과분할이면 더 큰 덩어리로 합치게 지시하면 된다(반대면 잘게). B는 무관한 과잉 대응, C는 조망이라는 MOC의 가치를 버리는 것이다.

# Block 3: 검색 품질 높이기 — Claude Code only

> 🎛️ **지휘자 원칙:** 기법을 외우지 말고 "이렇게 찾아줘"로 **Claude에게 시키며** 결과 차이를 판정하세요.

## EXPLAIN

기본 검색(B2)을 더 정확하게 만드는 네 가지 레버. 전부 임베딩 없이, Claude·grep·구조만으로.

### 레버 ① 질의 확장 폭 조절

너무 좁으면 못 찾고, 너무 넓으면 잡음이 섞인다.
- 못 찾을 때: "동의어·상위어·영문 표기까지 넓혀서 다시 찾아줘"
- 잡음 많을 때: "핵심 의미에 가까운 후보만 남겨줘"

### 레버 ② 메타데이터 필터 (B1 구조 활용)

frontmatter로 범위를 먼저 좁히면 정확도·속도 둘 다 올라간다.
- "`type: clipping`만", "`tags`에 브랜드 있는 것만", "2025년 이후 노트만"
- 후보가 많을수록 필터가 곧 품질이다.

### 레버 ③ MOC 경유 탐색

"전체에서 찾기"보다 "주제 지도에서 해당 주제로 좁힌 뒤 찾기"가 정확하다.
- "`_moc/`에서 가장 가까운 주제를 먼저 고르고, 그 주제 노트들 안에서 찾아줘"

### 레버 ④ 근거 요구 (환각 방지)

- "각 결과가 **왜** 관련 있는지 노트의 실제 문장을 인용해줘"
- "확실치 않으면 추측하지 말고 '관련 약함'으로 표시해"

### 한국어 팁

- 조사·어미 때문에 grep이 잘 빗나간다 → **어간/명사 위주로** 검색어를 주게 한다("'주거'와 '집' 둘 다로")
- 영문 개념은 한/영 병기로 확장("UX, 사용자경험 둘 다")

> 이 레버들을 검색 스킬(B2)에 녹이면, 매번 설명 없이 호출만으로 적용된다.

## EXECUTE

**Step 1: 확장 폭 비교**
- 같은 질문을 "좁게"와 "넓게(동의어 포함)"로 시켜 결과 차이를 본다.

**Step 2: 필터 좁히기**
- "이번엔 `type`/`tags`/기간으로 좁혀서 같은 질문을 다시 찾아줘."

**Step 3: MOC 경유 + 근거**
- "`_moc/`에서 주제를 먼저 고른 뒤 그 안에서 찾고, 각 결과의 근거 문장을 인용해줘."

**Step 4: 검색 스킬에 반영**
- "방금 쓴 확장·필터·근거 방식을 vault-search-skill에 기본값으로 넣어줘."

> ✅ **이렇게 되면 성공:** 같은 질문을 "넓게 vs 필터 적용"으로 돌려 **결과 차이를 한 가지라도 관찰**하고, 결과에 근거 문장이 붙으면 성공.

## QUIZ

**문제:** 임베딩 없이 에이전트 검색의 정확도를 올리는 레버가 아닌 것은?

| 선택지 | 내용 |
|--------|------|
| A | frontmatter(type·tags·기간) 필터로 범위 좁히기 |
| B | 동의어·한영 병기로 질의 확장 |
| C | 노트를 전부 임베딩해 벡터 거리로 정렬 |

**정답:** C — 그건 심화(B8) 벡터 방식이다. 기본 트랙의 레버는 질의 확장·메타필터·MOC 경유·근거 요구다. A·B는 임베딩 없이 바로 쓰는 핵심 레버다.

**적용 문제 (시나리오):** "리텐션 개선" 노트를 찾는데 결과에 관련 없는 게 섞이고, 진짜 관련 노트엔 "잔존율"이라고 적혀 있다. 가장 효과적인 한 수는?

| 선택지 | 내용 |
|--------|------|
| A | 질의를 "리텐션·잔존율·재방문" 등으로 넓히고, `type`/`tags`로 잡음을 거른 뒤, 근거 문장을 요구한다 |
| B | "리텐션"만으로 더 정확히 한 번 더 grep한다 |
| C | 노트 제목을 전부 "리텐션"으로 바꾼다 |

**정답:** A — 동의어 확장(잔존율)으로 리콜을 살리고, 메타필터로 잡음을 줄이고, 근거 요구로 정확도를 검증한다 — 세 레버의 조합. B는 "잔존율" 노트를 여전히 못 찾고, C는 과거 노트를 수작업으로 오염시키는 비현실적 대응이다.

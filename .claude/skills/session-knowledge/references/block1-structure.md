# Block 1: 검색을 위한 구조화 — index · schema · MOC 준비

## EXPLAIN

> 🎙️ **설명 대본 (이대로 말하듯, ≤6줄 — 낭독 금지, 요약만)**
> - 임베딩 이전에, **Vault가 검색되기 좋은 모양**이어야 한다 — 구조가 검색 품질의 절반.
> - Claude가 의존하는 신호 셋: **frontmatter · 파일명 · 링크/지도**. 폴더 깊이는 약한 신호.
> - 준비물 넷: `_index.md`(지도) · frontmatter 표준(schema는 CLAUDE.md에) · `_moc/` 자리 · 얕은 폴더.
> - 안티패턴 = "폴더만 깊게 예쁜데 검색은 안 되는 Vault". 폴더 미학 대신 메타·index·MOC에 투자.
> - 보안: 대외비·고객정보는 검색 대상에서 빼라(`_private/` 분리 + CLAUDE.md에 제외 명시).

> 🎛️ **지휘자 원칙:** 아래 구조물은 직접 만들지 않습니다. **Claude에게 "이렇게 만들어줘"라고 시키고** 결과를 검토하세요.

에이전트 검색(B2)을 잘하려면, 그 전에 **Vault가 검색되기 좋은 모양**이어야 한다. 임베딩 없이도 검색 품질의 절반은 "구조"에서 나온다.

### 왜 구조가 검색 품질을 좌우하나

Claude가 자료를 찾을 때 의존하는 신호는 셋: **frontmatter · 파일명 · 링크/지도**. 폴더 깊이는 약한 신호(AI는 폴더 트리를 잘 안 뒤짐). 이 세 신호를 일관되게 깔아두면 grep·읽기·추론이 훨씬 정확해진다.

### 준비물 ① Index(지도) — `_index.md`

Vault 최상위 대시보드. AI가 진입 시 가장 먼저 읽어 "여기 뭐가 있나"를 몇 초에 파악한다. 대분류와 핵심 노트로 가는 링크 + 한 줄 설명. 없으면 AI가 수백 개를 전수조사해야 한다.

> 1편 B5의 `index.md`를 이미 만들었다면 그걸 검색용으로 다듬으면 된다.

### 준비물 ② Schema(틀) — frontmatter 표준

AI가 노트에서 데이터를 **구조적으로 추출하는 틀**. "어떤 노트에 어떤 필드(type·tags·date·status)"를 정해 일관되게 채운다. 이 표준을 **CLAUDE.md에 적어두면** Claude가 매번 같은 틀로 읽고 필터한다(예: `--type clipping`, `tags: 브랜드`로 좁히기).

> 별도 schema 파일을 만들 필요 없다 — 규칙은 CLAUDE.md에. 일관성이 핵심.

### 준비물 ③ MOC(주제 지도) 자리 — `_moc/`

주제별 묶음 노트가 들어갈 자리. B4에서 Claude가 채운다. 지금은 빈 폴더 + "여기는 주제 지도" 한 줄이면 충분.

### 준비물 ④ 얕은 폴더 + CLAUDE.md에 구조 설명

폴더는 얕게(생애주기 정도), 정밀 분류는 frontmatter로. **Vault 구조 자체를 CLAUDE.md에 적어** Claude가 추론 대신 읽고 시작하게 한다.

> ⚠️ **흔한 안티패턴:** "폴더만 예쁘게 깊이 나눴는데 정작 검색은 안 되는 Vault." 폴더 미학에 시간을 쓰지 말고, frontmatter 일관성·index·MOC에 투자하라. AI는 폴더 모양이 아니라 메타데이터·링크·지도를 읽는다.

> 🔐 **보안 — 검색 대상에 넣을 것/뺄 것:** Claude Code는 대상 폴더의 노트를 **읽는다.** 대외비·고객정보·비밀번호가 든 노트는 **검색 대상에서 빼라**(`_private/` 같은 폴더로 분리 + 검색 스킬·CLAUDE.md에 제외 명시). "AI에게 넘겨도 되는 지식 / 안 되는 지식"을 먼저 가르는 게 구조화의 일부다.

## EXECUTE

> Claude에게 시키세요. 각 단계는 **설명 → 확인 → 실행**.

**Step 1: 현재 구조 진단을 Claude에게**
- "내 Vault를 훑어서 ①`_index.md`가 있는지 ②frontmatter가 일관된지 ③주제 지도가 있는지 점검하고, 검색이 잘 되게 보강할 점을 알려줘. **바로 고치지 말고 먼저 보고만.**"

**Step 2: Index 보강 시키기**
- "위 진단을 바탕으로 `_index.md`(대분류 + 핵심 노트 링크 + 한 줄 설명)를 만들어/다듬어줘."

**Step 3: Schema를 CLAUDE.md에**
- "내 노트 타입별 frontmatter 표준(type·tags·date 등)을 정리해서 Vault CLAUDE.md에 '검색용 규칙'으로 적어줘."

**Step 4: MOC 자리 만들기**
- "`_moc/` 폴더와 `_moc/_index.md` 빈 골격만 만들어줘. 내용은 나중에 채운다."

> ✅ **이렇게 되면 성공:** `_index.md`가 있고, CLAUDE.md에 frontmatter 표준이 적혀 있고, `_moc/` 자리가 생기면 성공 — 검색의 토대가 깔렸다.

## QUIZ

**문제:** 임베딩 없이도 검색 품질을 좌우하는 "구조" 신호가 아닌 것은?

| 선택지 | 내용 |
|--------|------|
| A | frontmatter(메타데이터)의 일관성 |
| B | `_index.md` 같은 지도 + 노트 간 링크 |
| C | 폴더를 최대한 깊고 세밀하게 나누기 |

**정답:** C — AI는 깊은 폴더 트리를 잘 안 뒤진다(약한 신호). 폴더는 얕게, 정밀 분류는 frontmatter로. A·B는 AI가 강하게 의존하는 신호라 검색 품질을 직접 끌어올린다.

---

**적용 문제 (시나리오):** 검색을 더 잘 좁히려고 노트마다 `type`·`tags`를 일관되게 채웠다. 이 효과를 검색에서 살리려면 추가로 무엇을 해야 하나?

| 선택지 | 내용 |
|--------|------|
| A | 그 frontmatter 표준(어떤 노트에 어떤 필드)을 CLAUDE.md에 적어 Claude가 매번 같은 틀로 읽게 한다 |
| B | 폴더를 type별로 다시 깊게 나눈다 |
| C | 모든 노트 제목에 type을 길게 적는다 |

**정답:** A — 일관된 frontmatter = AI의 구조적 추출 틀(Schema). 그 규칙을 CLAUDE.md에 두면 Claude가 매번 같은 기준으로 필터·검색한다. B는 깊은 폴더라 AI 탐색에 약하고 분류 마찰만 키운다. C는 제목 오염일 뿐 구조적 필터가 안 된다.

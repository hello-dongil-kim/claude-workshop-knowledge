# Block 5: 운영 — 갱신 · 점검 (Claude Code only)

> 🎛️ **지휘자 원칙:** "갱신해줘 / 점검해줘"로 **Claude에게 시킨다.**

## EXPLAIN

> 🎙️ **설명 대본 (이대로 말하듯, ≤6줄 — 낭독 금지, 요약만)**
> - 기본 트랙의 큰 장점: **운영 부담이 거의 없다** — 색인이 없어 새 노트가 바로 잡히고 항상 최신.
> - 그럼 운영에서 할 일 3가지: **구조물 갱신**(`_index.md`·MOC), **점검**(깨진 링크·고아·frontmatter 누락), **검색 스킬 다듬기**.
> - 사람 뷰 / 에이전트 뷰는 **짝** — 에이전트는 검색 스킬로, 사람은 Obsidian에서 훑는다.
> - 사람용 의미 검색(선택): **Smart Composer**(Vault RAG 채팅·멀티 LLM) / **Smart Connections**(유사노트 패널), 로컬 임베딩이면 키·비용 0.
> - 검색 규칙을 Vault `CLAUDE.md`에 박아두면 Claude가 매번 알아서 따른다. 캡스톤: 내 지식체계를 직접 설계.

기본 트랙의 큰 장점: **운영 부담이 거의 없다.** 에이전트 검색은 색인이 없어 **항상 최신**이기 때문이다.

### 색인이 없다 = 갱신이 필요 없다

새 노트를 추가하면 그냥 검색에 잡힌다(Claude가 매번 grep·읽기를 새로 함). 심화(B8) 벡터 트랙은 색인을 다시 만들어야 하지만, **기본 트랙은 그 단계가 없다.** 이게 무설치·무운영의 이점.

### 그럼 운영에서 뭘 하나 — 3가지

1. **구조물 갱신** — 자료가 많이 쌓이면 `_index.md`·MOC가 낡는다. "인덱스랑 주제 지도를 최신 노트 반영해서 갱신해줘" (월 1회쯤).
2. **점검(lint)** — 깨진 링크·고아 노트·빈 노트·frontmatter 누락. "Vault를 점검해서 깨진 링크·frontmatter 빠진 노트를 리포트해줘. **바로 고치지 말고 보고만.**" → 확인 후 수정.
3. **검색 스킬 다듬기** — 잘 안 잡히는 질문이 있으면 그 패턴을 vault-search-skill에 반영.

### 사람 뷰 / 에이전트 뷰 (이원화)

같은 원본을, **에이전트와 사람이 각자의 방식으로** 검색한다.

- **에이전트(Claude)** → 검색 스킬(`knowledge-find`)로 의미 검색 (이번에 만든 것)
- **사람(나)** → Obsidian 안에서. 세 단계로:
  1. 기본: 자체 검색·그래프뷰·백링크 (무설치)
  2. **사람용 의미 검색 (선택, 키리스 가능)** — Obsidian 플러그인이 노트를 로컬 임베딩해 "유사노트·시맨틱 검색"을 띄운다:
     - **Smart Composer** — Vault를 맥락으로 AI 채팅 + RAG 검색. 임베딩·채팅 공급자를 **멀티 LLM**(OpenAI/Gemini/Claude/로컬 Ollama)로 고를 수 있음.
     - **Smart Connections** — 노트 옆 유사노트 패널 위주.
  3. **로컬 임베딩(Ollama 등)** 을 고르면 **키·비용 0** — 기본 트랙의 무설치 철학과 같은 결. 한국어엔 `bge-m3` 같은 다국어 모델이 무난.

> 핵심: 에이전트 검색(Claude)과 사람용 의미 검색(플러그인)은 **경쟁이 아니라 짝**. 사람은 눈으로 훑고, 에이전트는 시켜서 찾는다. 둘 다 키리스로 갈 수 있다.

### CLAUDE.md에 검색 규칙 박기

Vault `CLAUDE.md`에 "찾을 땐 에이전트 검색(질의확장+필터+근거), 자료 많이 쌓이면 인덱스·MOC 갱신"을 적어두면 Claude가 매번 알아서 따른다. 스니펫: `templates/vault-claude-md-snippet.md`.

## EXECUTE

**Step 1: 점검 1회**
- "내 Vault 점검해줘 — 깨진 링크·빈 노트·frontmatter 누락. 보고만 하고, 고칠 건 내 확인 받고."

**Step 2: 구조 갱신**
- "최근 추가된 노트를 반영해서 `_index.md`와 `_moc/`를 갱신해줘."

**Step 3: CLAUDE.md에 검색 규칙**
- `templates/vault-claude-md-snippet.md`를 Vault CLAUDE.md에 붙이게 시키고 경로에 맞게 다듬기.

**Step 4: (선택) 사람용 의미 검색**
- Obsidian 커뮤니티 플러그인에서 **Smart Composer**(Vault RAG 채팅·멀티 LLM) 또는 **Smart Connections**(유사노트 패널) 설치.
- 임베딩 공급자를 고를 때 **로컬(Ollama 등)** 을 고르면 키·비용 0. 한국어는 다국어 임베딩(`bge-m3` 등) 권장.
- 노트를 열어 유사노트/시맨틱 검색이 뜨는지 확인.

> ✅ **이렇게 되면 성공:** 점검 리포트를 1회 받고, `_index.md`/MOC를 갱신하고, CLAUDE.md에 검색 규칙이 적히면 성공 — 운영 루프가 돈다(색인 갱신 없이도).

### 🧭 종합 — 내 지식체계를 직접 설계하기 (기본 트랙 캡스톤)

여기까지가 기본기다. 이제 **남의 시스템을 복사하는 게 아니라, 내 것을 설계할** 차례다. 정답은 없다 — 내 분야·규모·습관에 맞게 스스로 정한다.

> 먼저 **B0의 핵심 원리 6**을 다시 펼쳐보라. 아래 결정마다 "이건 어떤 원리를 적용한 건가?"를 짚으면 설계가 흔들리지 않는다.

종이에 적거나 Claude와 대화하며 결정해보라:

1. **검색 방식:** 내 vault 규모(수백? 수천?)면 에이전트 검색만으로 충분한가, 벡터(B8)까지 필요한가? 왜? (원리 3)
2. **구조:** 내 일에서 검색을 좌우할 frontmatter 필드는 무엇인가(type·tags·status·project…)? 내 schema는? (원리 2)
3. **지도:** MOC(주제 지도)가 내게 실제로 유용한가, 검색만으로 되나?
4. **운영 주기:** index·MOC 갱신을 언제 돌릴까(자료가 얼마나 쌓이면)? (원리 6)
5. **사람/에이전트 뷰:** 나는 주로 눈으로 훑나(사람 뷰 플러그인), 시켜서 찾나(에이전트 검색)? 둘의 비중은? (원리 4)
6. **공급자:** 심화로 간다면 키리스(로컬)로 갈까, OpenAI/Gemini로 갈까? 무엇을 기준으로? (원리 5)
7. **지속가능성:** 이 설계가 **6개월 뒤에도 유지될 이유**는? (지식관리는 시작보다 유지가 어렵다. 손 많이 가면 못 버틴다.)
8. **일상 연결:** 이 시스템을 내 **일/주간 루틴**에 어떻게 붙일까? (예: 주간 리뷰 때 Claude에게 던질 질문 3개를 미리 정해두기.)

> 이 8개에 내 답을 적으면 그게 **내 지식체계 설계도**다. 워크샵의 구성은 출발점일 뿐, 완성은 내 손에서 갈라진다.

## QUIZ

**문제:** 기본 트랙(에이전트 검색)의 운영이 가벼운 핵심 이유는?

| 선택지 | 내용 |
|--------|------|
| A | 색인이 없어 새 노트가 바로 검색돼, 색인 갱신 단계가 없다 |
| B | 노트를 자동으로 삭제해 수가 줄기 때문 |
| C | 검색을 한 달에 한 번만 할 수 있기 때문 |

**정답:** A — 에이전트 검색은 매번 grep·읽기를 새로 하므로 별도 색인 갱신이 불필요하다(항상 최신). B는 사실이 아니고, C도 틀림(언제든 검색 가능).

---

**적용 문제 (시나리오):** 기본 트랙으로 6개월 운영해 노트가 두 배가 됐다. 검색은 잘 되는데 "전체 조망"이 흐려졌다. 운영에서 할 일은?

| 선택지 | 내용 |
|--------|------|
| A | `_index.md`와 MOC를 최신 노트 반영해 갱신하고, 점검으로 깨진 링크를 정리한다 |
| B | 검색 색인을 다시 빌드한다 |
| C | 아무것도 안 해도 된다 — 색인이 없으니까 |

**정답:** A — 검색 자체는 최신이지만 조망용 구조물(index·MOC)은 시간이 지나면 낡는다 → 주기적 갱신 + 점검이 운영의 핵심. B는 기본 트랙엔 색인이 없어 해당 없음(그건 B8), C는 검색은 맞지만 조망(구조물)은 갱신이 필요하므로 틀렸다.
